# ME-DESIGN v1.7 — Architecture Proposal

> **Status:** Adopted Roadmap Blueprint  
> **Source:** ChatGPT Technical Review & Architectural Consultation (October 2026)  
> **Target Release:** v1.7.0+  
> **Guiding Principle:** Keep the core engine lightweight (0 mandatory runtime dependencies for AI coding agents), make deeper analysis capability-driven (opt-in parsers), and require empirical evidence before declaring an interface compliant or a repair successful.

---

## 1. Multi-Tier Operating Modes

ME-DESIGN separates execution into three distinct capability layers:

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 1. Core Mode — Minimal Overhead (0 Runtime Dependencies)                │
│    - Bespoke lexical scanner and shared source offsets                  │
│    - Shared Intermediate Representation (IR): ElementRecord, StyleRule  │
│    - Design token validation & deterministic pattern rules              │
│    - Transactional auto-repair with safe staging, backup & rollback     │
├─────────────────────────────────────────────────────────────────────────┤
│ 2. Extended Mode — Syntax-Aware Analysis (Opt-in Parsers)               │
│    - HTML: parse5 for standards-compliant HTML tree construction        │
│    - CSS: css-tree or PostCSS for selector specificity & nested at-rules│
│    - JSX/TSX: TypeScript compiler API or dedicated JSX parser           │
├─────────────────────────────────────────────────────────────────────────┤
│ 3. Verification Mode — Actual Rendered Behavior (Headless Chrome/CDP)   │
│    - Real computed styles, bounding box measurements (44px hit-targets) │
│    - Responsive layout stability & horizontal overflow detection        │
│    - Keyboard focus visibility & forced-colors high contrast simulation │
└─────────────────────────────────────────────────────────────────────────┘
```

The essential distinction: **Static analysis establishes that a rule appears to be satisfied in source code; browser verification proves that the rendered interface behaves correctly.** ME-DESIGN reports this distinction explicitly.

## 2. Shared Intermediate Representation (IR)

Rules must never independently rescan raw source text with ad-hoc regular expressions. Elements and style declarations are extracted once into a shared schema:

```typescript
type SourceRange = {
  startOffset: number;
  endOffset: number;
  startLine: number;
  startColumn: number;
};

type ElementRecord = {
  id: string;
  syntax: "html" | "jsx";
  tagName: string | null;
  componentName?: string;
  attributes: Record<string, string | null>;
  parentId?: string;
  children: string[];
  source: SourceRange;
  confidence: "exact" | "partial";
};

type StyleDeclaration = {
  property: string;
  value: string;
  important: boolean;
  source: SourceRange;
};

type StyleRule = {
  selectors: string[];
  declarations: StyleDeclaration[];
  atRulePath: string[];
  source: SourceRange;
  parseStatus: "parsed" | "partial" | "unsupported";
};

type AnalysisEvidence = {
  ruleId: string;
  status: "pass" | "fail" | "unknown" | "not-applicable";
  evidence: string[];
  sourceRanges: SourceRange[];
  method: "static" | "browser";
};
```

### Invariant Checks & Diagnostic Confidence

- **`:focus-visible` (MD001 / MD005):**
  - *Static:* Extracts selectors and declarations with source locations.
  - *Browser:* Emulates keyboard focus on interactive elements and measures computed outline/ring contrast.
- **44px Hit Targets (MD003 / MD106):**
  - *Static:* Scans for `min-width`, `min-height`, padding, and decoupled halos (`.touch-halo`).
  - *Browser:* Measures actual rendered `getBoundingClientRect()`:
    $$W_i = \operatorname{width}(\operatorname{rect}(e_i)), \quad H_i = \operatorname{height}(\operatorname{rect}(e_i))$$
    $$T_i = (W_i \ge 44 \land H_i \ge 44) ? 1 : 0$$
- **Reduced Motion (MD002):**
  - *Static:* Verifies enclosing `@media (prefers-reduced-motion: reduce)` at-rule blocks for matching animated selectors.
  - *Browser:* Emulates `prefers-reduced-motion` and verifies computed `animation-duration` and `transition-duration`.

## 3. Mathematically Grounded Q-Score Model

### 3.1 Hard-Gate Invariants vs Continuous Dimensions

The release decision must never be overridden or masked by an aggregate numeric score.

Let each mandatory invariant be $h_j \in \{\text{PASS}, \text{FAIL}, \text{INCOMPLETE}, \text{NOT-APPLICABLE}\}$.

$$\text{Gate} = \begin{cases}
\text{FAIL}, & \exists j: h_j = \text{FAIL} \\
\text{INCOMPLETE}, & \exists j: h_j = \text{INCOMPLETE} \\
\text{PASS}, & \text{all applicable mandatory invariants pass}
\end{cases}$$

### 3.2 Continuous Scoring Dimensions

| Dimension ($S_k$) | Weight ($w_k$) | Measurable Signals |
| :--- | :---: | :--- |
| **Contrast Quality** | 0.20 | Actual computed contrast ratios against target threshold $\tau_i$ |
| **Responsiveness** | 0.20 | Absence of horizontal overflow, clipped content, layout shifts |
| **Token Adherence** | 0.15 | Ratio of eligible declarations using approved design tokens |
| **Spacing & Geometry** | 0.15 | Spacing-scale adherence, concentric radii math, boundary clearance |
| **Typography** | 0.10 | Fluid scaling, line-height ratios, font-stack priority |
| **Interaction States** | 0.10 | Coverage of hover, active, focus-visible, disabled, loading |
| **Visual Consistency** | 0.10 | Palette harmonization, elevation hierarchy, squint-test focus |

### 3.3 Weighted Geometric Mean Formula

Continuous dimensions are combined using a weighted geometric mean to penalize catastrophic failures in any single dimension:

$$Q = 100 \cdot \prod_{k} \left(\max(\epsilon, S_k / 100)\right)^{w_k}$$

*(where $\sum w_k = 1.0$ and $\epsilon = 0.01$ prevents logarithmic singularities)*

### 3.4 Evidence Coverage Gating

Every dimension reports its evidence coverage:

$$E_k = 100 \cdot \frac{\text{weight of evaluated checks}}{\text{weight of all applicable checks}}$$

If overall evidence coverage $< 90\%$, the score is flagged as `DIAGNOSTIC_ONLY` / `INSUFFICIENT_EVIDENCE` rather than presenting an unverified passing score.

## 4. Transactional Auto-Repair Specification

File modifications in `medesign polish` must follow a fail-closed transactional lifecycle:

```
[1. Lock & Hash]
       │
[2. Transform in Memory]
       │
[3. Write to Staging (.medesign-stage-*)]
       │
[4. Pre-Commit Validation] ──(Failed)──> [Abort & Remove Staging]
       │ (Pass / Not Dry-Run)
[5. Create Backup (.medesign-backup-*)]
       │
[6. Atomic Rename / Commit]
       │
[7. Post-Commit Verification] ──(Failed)──> [Rollback to Backup & Verify Hash]
       │ (Pass)
[8. Release Lock & Cleanup]
```

### Reference Implementation Contract (`src/repair/transaction.js`)

```javascript
'use strict';
const fs = require('node:fs/promises');
const path = require('node:path');
const crypto = require('node:crypto');

function hash(data) {
  return crypto.createHash('sha256').update(data).digest('hex');
}

function siblingPath(target, label, extension = '') {
  return path.join(
    path.dirname(target),
    `.${path.basename(target, path.extname(target))}.medesign-${label}-${crypto.randomUUID()}${extension}`
  );
}

async function transactionalRepair({
  filePath,
  transform,
  validators,
  dryRun = false,
  keepBackup = false
}) {
  const target = path.resolve(filePath);
  const directory = path.dirname(target);
  const extension = path.extname(target);

  const lockPath = `${target}.medesign.lock`;
  let lock;
  let ownsLock = false;
  let stagePath;
  let backupPath;
  let committed = false;
  let preserveBackup = false;

  try {
    lock = await fs.open(lockPath, 'wx', 0o600);
    ownsLock = true;
    await lock.writeFile(JSON.stringify({ pid: process.pid, startedAt: new Date().toISOString() }));
    await lock.sync();

    const originalBytes = await fs.readFile(target);
    const originalHash = hash(originalBytes);
    const originalText = originalBytes.toString('utf8');

    const candidate = await transform(originalText, { filePath: target, originalHash });
    const candidateBytes = Buffer.from(candidate, 'utf8');
    const candidateHash = hash(candidateBytes);

    if (candidateHash === originalHash) {
      return { ok: true, changed: false, committed: false };
    }

    stagePath = siblingPath(target, 'stage', extension);
    await fs.writeFile(stagePath, candidateBytes);

    // Pre-commit validation
    const beforeCommit = await validateCandidate(stagePath, target, validators, 'pre-commit');
    if (!beforeCommit.ok) {
      return { ok: false, changed: true, committed: false, reason: 'candidate-validation-failed', validation: beforeCommit };
    }

    if (dryRun) {
      return { ok: true, dryRun: true, changed: true, committed: false, preview: candidate };
    }

    // Backup creation & Atomic rename
    backupPath = siblingPath(target, 'backup');
    await fs.writeFile(backupPath, originalBytes);

    await fs.rename(stagePath, target);
    stagePath = undefined;
    committed = true;

    // Post-commit validation
    const afterCommit = await validateCandidate(target, target, validators, 'post-commit');
    if (!afterCommit.ok) {
      await fs.writeFile(target, originalBytes); // Safe rollback
      committed = false;
      return { ok: false, changed: true, committed: false, rolledBack: true, reason: 'post-commit-validation-failed' };
    }

    return { ok: true, changed: true, committed: true, originalHash, candidateHash };
  } finally {
    if (stagePath) await fs.unlink(stagePath).catch(() => {});
    if (backupPath && !preserveBackup && !keepBackup) await fs.unlink(backupPath).catch(() => {});
    if (ownsLock && lock) {
      await lock.close().catch(() => {});
      await fs.unlink(lockPath).catch(() => {});
    }
  }
}
```
